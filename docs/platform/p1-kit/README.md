## 納品の流れ（P1・人が確認する）
1. 購入 → ココナラのトークルームで同意を確認し、ヒアリング（外部フォームには誘導しない）
2. 申込内容を確認。不足があれば1回だけ質問する
3. 申込内容から**氏名・連絡先を除いた必要項目だけ**を AI に渡し、テンプレートに沿って下書きを作る（AIサービスの学習利用はオフ）
4. 運営者が下書きを確認・修正（`common.md` の禁止表現チェックを通す）
5. PDF にして納品。作業時間を `ledger-template.csv` 形式で記録
6. 保存期間が過ぎたら申込内容と作業ファイルを削除し、削除日を記録

## 受付の上限（P1）
- 初回：各サービス先着3件（計12件）。初回納品と対応の合計は20時間まで。1件の実作業が見積もりの1.5倍を2件続けて超えた商品は受付停止。
- 月次更新（①②③のみ、任意申込）：各3名まで、月次対応は1か月6時間まで。④の月次は法的確認まで販売しない。ココナラ定期購入プランの規約確認まで販売開始不可。詳細は `subscription.md` 5章。

## 販売開始前に必要なこと（このキットの外）
- プライバシーポリシー・販売者情報・特定商取引法の表記の確定（オーナー）
- 使用するAIサービスのデータの扱い・学習利用の設定・国外での処理の確認と、必要な説明・同意の確定【要確認】
- 各販売プラットフォームの最新規約・手数料・禁止事項の確認と記録
- 最終版の ChatGPT 再レビュー → オーナーが公開・販売開始を判断

## 現在地ボードの実機確認（販売前に必須・ChatGPT 指摘）
4つのボードを Google ドライブにアップロードして Google スプレッドシートに変換し、**スマホのアプリ**と**PCのブラウザ**の両方で確認する。
- [x] 開いたとき最初に「スマホ」シートが表示される
- [x] 「スマホ」シートに入れた数字が「記録」（④は「模試の記録」）と「ボード」に正しく反映される
- [x] グラフで未入力の月が0として描かれず、実績と予定が正しく表示される
- [x] ④の6列の入力表（PCのスマホ幅表示とGoogle上の入力で確認。スマホアプリでの④の入力は③と同じ操作のため③で代表確認）と教科別の結果が、スマホで無理なく入力・閲覧できる
- [x] ②④はスマホで、①③はスマホとPCの両方で、毎月の入力から現在地の確認までが迷わずできる
確認できなかった項目は、スプレッドシートの修正、またはスマホ用Webページの検討（オーナー承認とレビューが必要）で対応する。

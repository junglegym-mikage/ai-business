# SNS運営の仕組み（Claude × ChatGPT の投稿エンジン）

目的：オーナーの手間を「週1回の承認」だけにして、Instagram（中心）に質の高いリールを出し続け、反応から学んで伸びる型を増やす。**「勝手にバズる」は保証できない**。保証できるのは「伸びる確率が上がる行動を、毎週休まず続けて改善する仕組み」。

## 1. やらないこと（アカウント停止・規約違反のため）
- フォロワー・いいね・再生の購入、自動いいね・自動フォロー、サクラ（別アカウントや身内での組織的な反応）、AIで作った偽のコメント・偽の利用者の声
- 他人の動画・音源・画像の無断転用、他社の商標や有名人の画像
- 「必ず稼げる」「合格保証」などの保証・断定、効果の具体的な数字（ココナラの景品表示法ルールにも抵触）
- Instagram の利用規約は、自動化ツールによる不正な反応の水増しを禁止している。ココナラも「SNSの数値を不当に操作するサービス」を出品禁止にしている

## 2. 役割分担
| 担当 | やること |
|---|---|
| Claude（制作・分析） | 毎週：①前週の数字を集計・分析 ②伸びた投稿の共通点を抽出 ③翌週の投稿5本（すべてリール）とストーリーズの企画 ④台本・字幕・キャプション・ハッシュタグ ⑤リール動画とストーリーズ画像の制作（縦型9:16、リールは15〜30秒、図解アニメ、顔出しなし）⑥コメントへの返信案 ⑦投稿の予約 |
| ChatGPT（独立レビュー） | 毎週：①冒頭2秒の掴み（フック）の強さを採点し、弱いものに代案 ②事実誤認・誇大表現・規約違反のチェック ③「なぜ伸びた／伸びなかったか」についてClaudeと別の見立てを出す |
| オーナー | 週1回、翌週分の投稿5本（リール）とストーリーズを見て「OK／やり直し」（5分程度）。コメント返信は1日15分以内。Instagramへのログイン |

## 3. 毎週の流れ
| 曜日 | 内容 |
|---|---|
| 日曜 | Claude：前週の数字を集計（最初はインサイトの画面をオーナーがスクショで共有、API連携後は自動）。分析レポートと翌週の企画5本を作成 |
| 日曜 | ChatGPT：企画・台本をレビュー → Claude が修正 |
| 月曜朝 | オーナー：完成動画5本を確認して承認 |
| 月曜 | Claude：Instagram の予約投稿で、週5本を配置（下の「投稿の割り振り」） |
| 毎日 | コメント返信は**1日15分以内**が目安。優先順位：①質問 ②購入を検討している人 ③事実の誤りなど重要な指摘。Claude が返信案を作り、オーナーが確認して送信する |

## 4. 伸びる確率を上げる作り方
- **冒頭2秒で結論か問い**：「事務作業、月何時間か数えたことある？」「毎月3万円、20年でいくらになる？（仮定）」
- **保存・送信したくなる中身**：そのまま使えるテンプレート、チェックリスト、計算の型（保存・送信はおすすめ表示に効きやすい反応）
- **シリーズ化**：「AIで道筋を作る #1〜」のように続き物にして、次も見たくなる形にする
- **同じテーマで掴みを変えて試す**：Instagram の「試験的なリール」（フォロワー以外にだけ先に見せる機能）がアカウントで使えれば、1つのテーマで掴み違いを2本出して、反応が良い方を本投稿にする
- **オリジナル**：図解・数字・台本はすべて自作。音源は Instagram 内の利用可能な音源のみ
- **1つの動画を複数の場所に**：Instagram に加え、TikTok・YouTube ショート・Threads にも同じ動画を出して当たる機会を増やす（各サービスのロゴ透かしが入らない元動画を使う）。アカウント作成はオーナー
- **導線**：プロフィールのリンク → ココナラ。投稿で売り込まず、最後の1枚・最後の2秒だけ「詳しくはプロフィールから」

## 5. 投稿量と割り振り（最初の4週間）
- **週5本（すべてリール）＋投稿日ごとにストーリーズ2枚、4週間でリール20本**（オーナー決定 2026-10-31：全投稿リール、ストーリーズも上げる）。図解をじっくり見せたい回も、スライドを順に見せるリールにする。本数をこなすことより、テーマ・冒頭の掴み・最後の案内（CTA）を比べて学ぶことを優先する。制作の負担と成果を見て、5週目以降に週7本へ増やすか判断する
- アカウントの共通テーマ：**「AIで、仕事・お金・目標・受験の計画と管理を効率化する」**。4事業はシリーズとして表紙・冒頭・ハッシュタグ・プロフィールのリンクで区別する
- 売上が出る事業が見えたら、その事業だけ独立したアカウントに分けるか判断する

| 週 | 月 | 火 | 水 | 木 | 土 |
|---|---|---|---|---|---|
| 毎週 | ①リール | ②リール | ③リール | ④リール | ①リール |
（①が売上の主軸のため4週で①を8本、②③④を各4本。形式は「動きで見せる図解」と「スライドを順に見せる」の2種類を交互に使い、どちらが保存・視聴時間で伸びるかを比べる）

### 5.0.1 ストーリーズ（投稿日ごとに2枚）
| 順 | 中身 | 貼るスタンプ（投稿時にアプリで追加） |
|---|---|---|
| 1枚目（朝） | その日のテーマの質問（例：事務作業、月に何時間？） | アンケート（2択）。中央下を空けてある |
| 2枚目（リール公開後） | 新しいリールの案内 | 公開したリールを「ストーリーズでシェア」で中央に重ねる |
- アンケートの結果は次の企画の材料にする（個人を特定する使い方はしない）。回答者への個別DMはしない
- 反応が多かった回は、ハイライト「①経営」「②家計」「③目標」「④受験」「ご利用の前に」に残す
- 画像は `sns/tools/render.py` で作る（上250px・下340pxはアプリの表示と重なるため文字を置かない）

## 5.0 プロフィールのリンクの仕様
- Instagram のプロフィールのリンク機能（最大5件まで登録できる。件数はアプリで要確認）に、ココナラの4つの出品ページを事業ごとに別々に登録する。表示名は「①経営のAI化」「②家計・積立」「③目標ロードマップ」「④受験ロードマップ」。①を一番上に置く
- 流入の判別：Instagram のインサイトで「リンクごとのタップ数」を見る。ココナラ側は出品ページごとの閲覧数で照合する（ココナラの URL に勝手なパラメータを付けたり外部の短縮URLを使ったりしない）
- 投稿の最後の案内は、事業名を入れて「④受験ロードマップはプロフィールのリンクから」とし、どのリンクを押せばよいか迷わせない
- 4事業の一覧ページ（自社サイト）を挟む方法は、ココナラ外への誘導と誤解されないよう使わない

投稿ごとの管理は `sns-posts.csv`（事業・形式・テーマ・掴み・CTA・数字・ココナラへの到達）に記録する。

## 5.1 見る数字（バズより売上につながるかを見る）
| 順番 | 数字 | 取り方 |
|---|---|---|
| 1 | フォロワー以外への表示（リーチ） | インサイト |
| 2 | 保存・送信（シェア）・平均視聴時間 | インサイト |
| 3 | プロフィールへのアクセス | インサイト |
| 4 | プロフィールのリンクのタップ（事業別のリンク） | インサイト |
| 5 | ココナラの出品ページの閲覧（事業別） | ココナラの管理画面 |
| 6 | 問い合わせ・購入 | ココナラ |
| 7 | 購入1件あたりの制作・対応時間 | `ledger-template.csv` |

- 成功の判定は「再生数」ではなく「4→5→6につながったか」。再生が少なくても購入につながった型は残す。バズっても売れない型は増やさない
- 4週間の「伸びた型を2つ以上」は保証ではなく**検証の目標**。広告は使わない（使う場合は上限額をオーナーが承認）

## 5.2 増量期（オーナー決定 2026-10-31：「バズるまでは1日リール3本＋ストーリー1本」。ChatGPT「確定でよい」）
5章の週5本に代えて、次の判定までこの量で運用する。
- **量**：1日リール3本（7:30／12:15／20:30）＋ストーリー1本（その日の質問＋2択アンケート）。週21本の内訳：①7（毎日1本）②5 ③5 ④4
- **制作**：台本（文章）から動画を作るテンプレート生成（スライド型・リスト型・棒グラフ型）で週1回まとめて制作。同じテーマの言い換え連発はしない（`sns-posts.csv` でテーマの重複を管理）。ChatGPT が週1回まとめて禁止表現・事実を確認、オーナーが週1回まとめてOK
- **アンケート**：全曜日2択（例：水「決めてる／まだ決めていない」、木「毎回見返す／あまり見返さない」）。結果は企画の改善だけに使い、個別DMはしない
- **「バズった」の判定**：各投稿は公開後7日間の数値で集計。判定期間は4週間。①1本でも再生1万回、または②フォロワー外リーチ5,000以上が2本 → その型を増やし、本数を見直す。4週間で届かなければ、本数を続けるかをデータで再判断
- **型を外す判断**：平均視聴時間だけで決めない。視聴維持率（尺に対する割合）・保存率・シェア率を合わせて見る
- **投稿方法**：
  - A（開始時）：オーナーがスマホで投稿。Claude がその日の動画・ストーリー画像・キャプションを送る。投稿はオーナー承認のうえ。最初の2週間は投稿作業の実時間を `ledger-template.csv` に記録
  - B（検証後に判断）：Meta 公式のコンテンツ公開API。Facebookページ連携・Metaアプリ・権限・動画URLの要件・ストーリーズ投稿（アンケートスタンプは付けられない）を実機で検証してから判断し、導入はオーナー承認。動画を公開URL（公開リポジトリ）から取り込ませる場合も、公開してよい完成素材だけを置く
  - 理由：Claude の環境からブラウザ版 Instagram へ動画ファイルを渡せない（2026-10-31 確認。プロフィール写真のような小さな画像は可）

## 6. 自動化の段階
| 段階 | 投稿の方法 | 費用 |
|---|---|---|
| 1（今すぐ） | Claude が動画とキャプションを作り、オーナーのスマホ（または Claude がアプリ内ブラウザ）で Instagram の予約投稿に設定。公開はオーナー承認後 | 0円 |
| 2（**保留**。4週間の手動運用で内容と売上導線の効果を確かめてから費用対効果を判断） | Meta の投稿API（Content Publishing）による自動投稿・自動集計 | API の利用料はないが、無料で簡単に動くわけではない：プロアカウント、Facebook ページとの連携、Meta アプリの作成と審査・権限、アクセストークンの管理、動画を公開URLに置く仕組み、投稿処理とエラー対応が必要。開発・運用の手間と、置き場所によっては費用がかかる。始める場合はオーナーの承認を得る |

当面は Instagram 公式の予約投稿を使う。API の投稿上限は24時間あたり最大100件程度（公式ドキュメント。数値は要確認）。

## 6.1 自動投稿（投稿方法B）の仕組み（オーナー指示 2026-10-31「やってくれ」。ChatGPT レビューの必須修正を反映）
Meta 公式の Instagram API with Instagram Login（Facebookページ不要。権限 instagram_business_basic・instagram_business_content_publish。リール・ストーリーズ可。動画は公開URLから取り込み。アンケートスタンプは付けられない）。
- **実行**：GitHub Actions（公開リポジトリのため無料）が30分ごとに `sns/tools/ig_publish.py` を実行。ワークフローは既定ブランチ（main）に置く必要があるため、ワークフロー1ファイルだけのPRをオーナー承認で main に入れる。PR からは起動しない
- **投稿表**：`sns/queue.json`（`build_queue.py` で台本とキャプションから作る）
- **承認**：オーナー指示（2026-10-31「承認の必要なし」）により、ChatGPT レビュー済みの投稿表はその時点で Claude が承認として記録する（オーナーは止めたいときだけ指示・停止スイッチ）。記録は `ig_publish.py approve <日付>` で `approvals.json` に承認ハッシュを記録。ハッシュは投稿日時・形式・ファイルの中身・キャプション・アカウント名から計算するため、承認後に1つでも変わると自動的に未承認になる
- **二重投稿の防止**：`posted.json` に状態を記録。processing（GitHub に記録してから API を呼ぶ）→ published（メディアID）／failed（公開前の失敗。次回再試行）／unknown（公開できたか不明。自動で再投稿せずオーナー確認）。記録できないときは投稿しない。同時実行なし。予定から3時間を過ぎたものは投稿しない
- **安全装置**：リポジトリ変数 `IG_PUBLISH_ENABLED=true` のときだけ投稿（手動実行でも同じ。check は投稿しない）。投稿前にアカウント名が `process_performance_ai` か確認。外部 Action はコミットSHAで固定。トークンはログに出さない
- **トークン**：オーナーが生成し、GitHub Secrets `IG_ACCESS_TOKEN` に自分で登録（Claude は見ない・入力しない）。発行日をリポジトリ変数 `IG_TOKEN_ISSUED` に入れる。50日目から警告、58日目で投稿を止める → オーナーが再発行
- **素材**：公開リポジトリの完成素材だけを jsDelivr の URL（コミット固定）で取り込ませる
- **切り替え**：check（アカウント確認）→ オーナーが内容を確認した1本でテスト投稿 → 成功したら、本番への切り替えを別途オーナーが承認
- **オーナーの作業**：①Claude の画面のブラウザで Facebook にログインし、Meta 開発者に登録 ②（Claude がアプリを作成し、Instagram のテスターを追加）③オーナーがトークンの生成ボタンを押して Instagram でログイン ④GitHub の Settings → Secrets and variables → Actions で `IG_ACCESS_TOKEN`（Secret）と `IG_TOKEN_ISSUED`・`IG_PUBLISH_ENABLED`（Variables）を登録 ⑤main へのPRを承認

## 7. 最初の4週間の目標（予測ではなく行動の目標）
- リール20本とストーリーズを予定どおり出す
- 掴み違いの比較を最低5組行う
- 伸びた型を2つ以上見つける

## B. 採用する運営（全体像）
```
[日曜] Claude の定期タスク（自動起動）
   └ 前週の数字を集計（インサイトのスクショ → 段階2で自動）
   └ 翌週の投稿5本を企画・制作（動画・画像・キャプション・返信案）
   └ GitHub に「今週の投稿案」として PR を作成 → ChatGPT がレビュー
     （導入予定：Codex の自動レビュー。テストPRで動作確認するまでは ChatGPT の手動レビュー）
   └ Claude が指摘を直す
[月曜朝] オーナーがスマホで PR を見て「OK」（5分）
[月曜] 予約投稿：Instagram 本投稿／（採用候補）試験的なリール／YouTube ショート／Threads
```

## C. 売上につなげる仕掛け
- **無料サンプル（リードマグネット）**：記入例入りの現在地ボード（架空データ、Googleスプレッドシートの閲覧用コピー）。コメントのキーワードで自動DM。「入力すると現在地と道筋が自動で出る」を体験してもらい、自分用はココナラで、という流れ
- 投稿の最後は事業名入りの案内（「④受験ロードマップはプロフィールのリンクから」）
- 無料サンプルには個人情報の入力欄を作らない。DMでも個人情報を求めない

## C.1 試験的なリールで掴みを比べるルール
- 同じテーマ・同じ中身で、**冒頭の掴みだけ**を変えた2本を作る
- できるだけ同じ曜日・時間帯・同じ長さで出す
- 24時間後の再生数だけで決めず、平均視聴時間・送信（シェア）・保存・プロフィールアクセスを合わせて比べる
- 反応が良い方を通常公開する。差が小さいときは「引き分け」として次の比較に回す（無理に勝ち負けを決めない）

## C.2 自動DMの範囲（ココナラの規約との関係）
- Instagram で出会った**新しい見込み客**に、無料サンプルとココナラの該当出品ページを案内するのは、ココナラで知り合った購入者を外へ誘導する行為（禁止）とは別
- DM で送るのは**無料サンプルの閲覧リンクと、該当するココナラ出品ページのみ**。メールアドレス・電話番号・LINE登録・外部決済への誘導はしない
- ココナラで購入した人への納品・連絡は、引き続きココナラ内で完結させる

## D. 守ること（再掲）
フォロワー・反応の購入、非公式ツール、サクラ、偽の声、AIアバターでの実在しない利用者、保証・効果の数字は使わない。AIで制作していることはプロフィールに明記する。
